## 1. Method, sample, calls

- Per bid: `prepare_bid` (reframe, doc_classify, align; cache-backed) gives the ACTIVE constraints, the catalogue and the alignments.
- Sample: candidates of the bid pool split into terciles of `text_chars` = len(json of specifications) + len(description) + len(brochure_text) (missing = 0): low / mid / high; seeded draw inside each stratum (as even as possible).
- Requests: for every sampled candidate and every active HARD constraint, one `normalise` request whose text is up to 3 of the candidate's own free-text units (spec entries, description / brochure sentences) with the highest token overlap with the constraint's attribute, spec_name and commercial_text, capped at 500 chars. No overlapping unit = no request (evidence none by construction). Pairs that already have a non-UNKNOWN structured status get no request.
- BEFORE = structured evidence only (`compliance_matrix`, no normalised). AFTER = structured + GROUNDED normalised values (value occurs in the snippet; ungrounded results are reported, never used).
- Evidence share = share of sampled candidates whose status is not UNKNOWN.

## 6. Caveats

- Snippet selection is lexical: a constraint whose words never appear in the candidate's text gets no request, so the AFTER share is a lower bound for what a semantic retriever could find.
- Sample sizes are small (about 12-20 candidates per bid, 3 strata); shares carry wide uncertainty (one candidate = 5-8 percentage points). Two bids only.
- Only grounded values count; a correct but re-phrased value (e.g. 'one HP' for '1 HP') is classed ungrounded.
- Results hold for the sampled bids and strata. Extrapolating to the full pool or other bids is a rough estimate at best; strata are terciles of THIS pool's text volume.
- Requests are made only for pairs without structured evidence, so AFTER >= BEFORE by construction (normalised values never overwrite structured rows in this setup; for unaligned attributes they are the only evidence).
